# Image identity and initial update reads

This supplements [images and updates](images-updates.md) for #229, #231 and #230. Locations refer to `8a14401325863f5153cebc0fa67ef44854184609`. These role rules replace uniform manifest-only comparisons; M2, M4, M5, M6 and executor safety authority remain binding.
## Identity roles and boundary types

Classify each image from **unqualified** inspect: Descriptor absent means classic; present means containerd and requires its digest to equal that inspect ID. Descriptor media type never decides the store. One local resolver in `backend/internal/imageupdate/children/identity` preserves the roles below.

| Role | Producer and meaning | Classic | Containerd |
| --- | --- | --- | --- |
| L: local ID | Image inspect **without platform**; container `.Image` and summary `ImageID` | Config digest | Pulled index or manifest digest |
| N: native key | Classic L; containerd container `ImageManifestDescriptor`, otherwise explicit-platform inspect Descriptor | L | Platform-manifest digest |
| P: platform | Container platform; effective Compose platform for service lookup; image-only reads use daemon-default OS/architecture/variant (`docker info` OSType/Architecture, unqualified inspect best-match variant; normalize architecture to OCI names) | Exact selected platform | Exact selected platform must have a locally available image child; otherwise unknown |
| R: registry candidate | Verified descriptor/config chain of the latest selected tag at P; no current-image registry lookup | R.config: candidate config digest | R.manifest: candidate platform-manifest digest |
| T: legacy top-level digest | Registry index/single-manifest descriptor or first RepoDigest, including legacy ImageUpdateRecord current/latest fields | Display or legacy pull reference only | Never N, R.config, R.manifest or E proof |
| E: expected post-pull local ID | Executor predicts before admission/pull of the immutable R.manifest reference | R.config | R.manifest |

Use distinct Go **named types, not aliases**, at the resolver boundary: `LocalID`, `NativeKey`, `Platform`, `RegistryConfig`, `RegistryManifest`, `RegistryCandidate`, `ExpectedLocalID` and mandatory `TopLevelDigest`. Only validated constructors convert DTO/storage strings; only the store-aware resolver projects R into a native comparison key or E. L/N/R/P/E/T cannot be interchanged by plain string assignment/comparison. `MatchesExpected(LocalID, ExpectedLocalID)` is the explicit checked E-to-local comparison bridge. TopLevelDigest must not be implicitly comparable with NativeKey, RegistryManifest or RegistryConfig. T is display or legacy pull-reference only: never eligibility, rebuild detection or identity. Record projection requires explicit validated native provenance; merely populating Platform cannot upgrade T, and unvalidated records stay unknown. R.native below means R.config or R.manifest for that store, not a new field. Do not scatter casts through consumers.
## Binding comparison rules

1. Compare L only with L in local fences. Platform-qualified inspect supplies N/P, **never L**: preserve L from unqualified inspect even when qualified inspect changes ID to a manifest on the native platform. Pins/reference/guard lookups remain unqualified.
2. Current versus candidate: classic compares N (=L) with R.config; containerd compares N with R.manifest. Equal keys mean current; changed keys use existing version/rebuild policy. Config-equal re-push is current under classic and rebuild under containerd; an index change for another platform is current. Never pair classic N with R.manifest.
3. If at least one current replica exists and E equals its current L for **every configured replica**, skip that selection as current with existing declared `job.skipped`; exclude it before admission. If all selections are skipped, produce no receipt/pull/recreate/restore point. Recheck defensively before effects on already-admitted work; mixed/different replicas and absent desired services still require correction, not a representative-only or vacuous skip.
4. Post-pull inspect of the immutable manifest yields actual L; compare it with frozen E and check P. Post-deploy compare every container `.Image` (L) with E. Use P for candidate lookup, pull and N resolution; a qualified post-pull inspect may verify N/P but cannot replace L. Deploy retains pull-never.
5. Pins, sharing, protections, observed revisions and rollback use L. A shared N/config cannot excuse a different L. Persist only L/P and local containerd N in encrypted snapshots; `ServiceImage.Digest` is verified local N under containerd and is explicitly cleared under classic, including carried prior bindings and post-pull desired snapshots. Hash stable local evidence only.
6. Unknown roles, inconsistent/missing required descriptor, ambiguous P or unavailable local platform mean unknown/unavailable with existing typed reasons. For containerd, prefer the container descriptor's N/P; otherwise explicit P inspect (API 1.49+) or unique Available image-kind manifest child at P (API 1.48+). Below API 1.48 is unavailable; ignore attestations. Two available children are not ambiguous for image-only reads: choose daemon-default P, not array order or any-other-available fallback.

The v7 selection stays `{Digest: R.manifest, ImageID: E, Platform: P}` for updates; restore carries saved L/local evidence without pulling. E is never optional or rediscovered after admission. Restart retains the frozen receipt, no replay, unknown holds and no false baseline. Capture, baseline/policy reads and point availability remain local with the registry offline. No contract bump, new wire fields, migration, protection config column or export; all shipped migrations 001–009 are immutable. Local RepoTags/RepoDigests supply repository provenance only, with no historical fetch; absent repository match means local.

## Initial/default read decision (F1)

Every successful policy read carries a proven nonempty target identity. Revision zero obtains the current identity through the existing local baseline-status port even if `available=false`, without saving/incrementing the policy. At the hub, validate copied identity **and both revisions** against `^[a-f0-9]{64}$`, including local and remote results; length alone is insufficient. Remote decode validates the success/data shape and required fields before copying. Transport/malformed responses become declared `update.check-unavailable`; preserve existing typed authorization/target failures. An offline revision-zero UI read shows a translated neutral unavailable state with retry and no fabricated identity/edit controls. Saved policies retain their binding/stale/offline semantics; save revalidates live identity/revision, and an existing policy can still be disabled offline.

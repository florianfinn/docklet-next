## Identity model (F2)

Use one Docker-boundary resolver in `backend/internal/imageupdate/children/identity`, shared by observation and lifecycle code. Its **local identity set** has typed members: daemon-local ID, config digest, repository-qualified repo digests, platform-manifest digest, optional index digest, exact OS/architecture/variant, and the evidence linking them. A digest string alone never declares its role. Names, tags, labels and overlapping untyped sets do not prove identity.
The **registry triple** is optional index digest, platform-manifest digest and config digest, resolved from one immutable descriptor chain. A single-manifest reference has no index member. Resolve the original descriptor before selecting its platform; verify returned content digests and exact platform. Current/candidate comparison always uses platform-manifest digests, including manifests with identical configs.
Evaluate every repo digest belonging to the normalized repository against local platform/config evidence; never choose the first array member. If more than one distinct current platform manifest remains plausible, report unknown/unavailable rather than guessing which is deployed. Version and rebuild eligibility require one proven current manifest.

| Boundary | Matching rule |
| --- | --- |
| Classic store | Without a multi-platform descriptor, local ID must equal the registry config digest; verify platform and repository provenance. Repo digests locate the immutable registry chain, but do not substitute for the config comparison. |
| Containerd store | Local ID must equal its inspect descriptor digest. Select the exact locally available platform manifest using platform inspect (API 1.49+) or available image-kind manifest summaries (API 1.48+); its digest must equal the registry platform manifest. An index ID matches only through this platform child, never just through a shared index. A direct manifest ID matches the platform manifest. |
| Config evidence | Classic IDs already prove the config digest. A verified containerd local manifest plus the immutable registry manifest proves its referenced config digest. If registry evidence is unavailable, use a read-only image export of the exact local ID and hash the original referenced config bytes, checking the index/manifest/config chain and platform. Inspect `Config`/`RootFS` are incomplete projections and cannot reconstruct that hash. Bound metadata to 8 MiB, stream/discard layers with context cancellation and the Docker API deadline; never extract files. Missing/ambiguous evidence refuses check/capture, with the existing typed unavailable reason. |
| Local equality | Pins, sharing, drift, tag races and running-container verification compare exact full daemon-local IDs on the same executor/registration. Config equality cannot excuse a different local object. Use container `ImageManifestDescriptor`, when supplied, to check the selected platform too. |
| Admission and pull | Freeze registry triple and platform before pull; update selections have no local ID yet. Pull by the frozen platform-manifest reference, resolve the returned local identity, verify the frozen triple, then put that actual local ID in the desired snapshot and run pin. Restore selections already contain the saved local identity. |

Persist local ID **and config digest**, platform and proven manifest/index evidence in encrypted baselines/points and point/run pin ownership; keep references separate. Durable protection keys remain `(local ID, reason, owner)` with config evidence in an additional field, never a config-keyed alias. Tag pins are verified against that local ID. Resolve all configured replicas, including partial-source images; unrelated/one-off workloads remain optional evidence. No registry availability is needed to restore a completely captured local point.
Add the pin evidence field with a new forward migration; never edit 006–009. Missing identity evidence makes a point unavailable; no legacy backfill or baseline bootstrap. Restore-intent size checks must measure all new fields. Restart reopens the same evidence; failed/unknown runs retain holds and never establish a baseline.
The frozen selection changes the wire contract: explicit `configDigest`, `manifestDigest`, optional `indexDigest`, and `imageId` required only for restore. Update `Digest` callers to the declared manifest field. Regenerate OpenAPI/TypeScript, validate at admission and remote decode, and advance agent contract/minimum to v8 through the #229 contract owner before dependent consumer changes. Keep Edge transport code read-only.

## Initial/default read decision (F1)

The producer returns a nonempty, proven identity on every successful policy read. For revision zero, resolve the current target using the existing baseline-status port, even when `available=false`; copy its identity into the response without saving a policy or incrementing revision. Missing targets or unavailable executors return typed failure, never an empty success. For saved policies, preserve the saved binding and stale/offline semantics; reading must not silently rebind policy/candidate authority. Save still revalidates live target and revision. Keep the strict UI identity decoder.

## Producer fixtures and provenance

Read-only sandbox capture on 2026-10-26 recorded existing busybox and nginx image inspect JSON, nginx container inspect JSON, platform-qualified inspect, manifest summaries, daemon version and driver status. No container, tag, image cache or runtime configuration was changed. The container/image pair agrees on its index local ID; the container additionally supplies a distinct platform manifest descriptor. Busybox default and platform inspect return index and manifest IDs respectively. Raw captures and hashes remain private coordinator evidence.
Capture commands use `docker -H <approved-loopback-endpoint> image inspect <existing-ref>` and `container inspect <existing-id>`; also record `image inspect --platform linux/amd64`, and the read-only API `images/<ref>/json?manifests=1`. Record exact argv, UTC time, API/Engine versions, store, SHA-256 and selection rationale privately. Never create a fixture workload or pull/tag an image in this phase.
Classic shapes are source-derived, not a live classic-store acceptance claim: Moby v28.5.1 commit `f8215cc266744ef195a50a70d427c345da2acdbb`, retrieved 2026-10-26, Apache-2.0. [Classic image inspect](https://github.com/moby/moby/blob/f8215cc266744ef195a50a70d427c345da2acdbb/daemon/images/image_inspect.go#L58), [config storage](https://github.com/moby/moby/blob/f8215cc266744ef195a50a70d427c345da2acdbb/image/store.go#L152), [container inspect](https://github.com/moby/moby/blob/f8215cc266744ef195a50a70d427c345da2acdbb/daemon/inspect.go#L153) and [containerd inspect](https://github.com/moby/moby/blob/f8215cc266744ef195a50a70d427c345da2acdbb/daemon/containerd/image_inspect.go#L82) establish the roles. In phase 2 derive minimal structural fixtures from those real responses, preserving ID relationships, nulls, field absence and descriptor/platform shapes. Sanitize environment, labels, mounts, names, paths and network details to reserved examples; pair with immutable registry manifests/configs. Explicitly label classic cases source-derived.

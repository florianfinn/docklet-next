This supplements [images and updates](images-updates.md) for #229, #231 and #230. Repository locations refer to `8a14401325863f5153cebc0fa67ef44854184609`. The store-native comparison rules replace uniform manifest-only comparison for classic images. M2, M4, M5, M6 and executor safety authority remain binding.

## Store-native identity (F2)

One Docker-boundary resolver in `backend/internal/imageupdate/children/identity` supplies **local evidence only**: full daemon-local ID, exact OS/architecture/variant and, for containerd, the local platform-manifest digest. Classify each inspected image independently: `Descriptor == nil` means classic; present means containerd and requires `ID == Descriptor.Digest`. Descriptor media type does not decide the store. Index and direct-manifest descriptors both identify containerd images.
The registry observation retains `{Digest, ConfigDigest}`: verified platform-manifest digest and config digest of the **latest selected reference**, at the exact local platform. Verify the candidate descriptor/config chain; any top-level index digest is discovery-only. There are no registry calls for the current image's identity, historical RepoDigest walks or current-manifest ambiguity rules. Local RepoTags/RepoDigests establish normalized repository provenance without fetching their targets; no repository match means `local`.

| Store/boundary | Rule |
| --- | --- |
| Classic | The native key is local ID, which equals the config digest. Compare it with the latest registry `ConfigDigest`. The local inspect platform supplies OS/architecture/variant. A classic container has no `ImageManifestDescriptor`. |
| Containerd | The native key is the local platform-manifest digest. For a container, prefer its `ImageManifestDescriptor` digest and platform. Otherwise inspect the exact requested platform (API 1.49+); otherwise select a unique `Manifests` child with Kind=image, Available=true and exact platform (API 1.48+). Reject attestations, unavailable/ambiguous children and inconsistent descriptors. A direct-manifest image uses that manifest digest. |
| Platform | Carry the container descriptor's platform, or the effective Compose platform, into every local lookup and candidate lookup. Pass the platform option to inspect and pull for non-default platforms; unqualified `ImageInspect(id)` cannot override a running container's platform. A containerd engine below API 1.48, or without sufficient local evidence, returns typed unavailable, never “current”. |
| Classification | Equal native keys mean current. A changed key is version or rebuild under the existing version-label/tag policy. A config-equal re-push is current under classic and rebuild under containerd if its platform manifest changed. A changed index affecting only another platform is current. `CurrentDigest` and `LatestDigest` use the same store-native role within one observation; compare only like roles/platforms. |
| Local fences | Pins, sharing, drift, tag races, restoration and all running-container checks still compare exact full local IDs on the same executor/registration. Shared configs or manifest aliases never excuse a different local object. |
| Frozen selection | Preflight runs on the executor and classifies the source local image there. Before admission/pull it sets existing `ImageSelection.Digest` to the candidate platform manifest and `ImageSelection.ImageID` to the expected post-pull local ID: candidate config digest for classic, candidate platform-manifest digest for containerd. Neither field is optional for an update. |
| Pull and execute | Pull `repo@<frozen platform manifest>` with the selected platform; inspect the result and require the predicted local ID and exact platform before pinning/tagging. Keep source revision/identity barriers after pull and before effects. Never discover or fill in a missing selection ID after admission; concurrent pulls/tag movers and late inspections cannot redefine the frozen intent. |

Persist only local ID, exact platform and containerd platform-manifest evidence in encrypted baseline/point snapshot JSON. Reuse `ServiceImage.Digest` for the local containerd manifest (absent under classic); expose it through the existing optional point digest. Hash only stable local evidence, never registry-derived evidence or inspect timing. Required configured replicas, including partial-source images, share this rule; unrelated/one-off containers remain optional evidence. Capture, baseline/policy reads, point availability and restore work with the registry offline. Point/run protections and tag pins retain local-ID keys and existing ownership/holds.
The existing `{Digest, ImageID}` selection, point DTO and contract v7 suffice. No contract bump, new wire fields, migration, protection config column or image export is needed. All shipped migrations 001–009 remain immutable. A missing local ID is malformed input, not an admitted transitional state; restart uses the frozen receipt and never replays a pull or fills in an ID. Failed/unknown runs retain holds and do not establish a baseline.

## Initial/default read decision (F1)

Every successful policy read carries a proven nonempty target identity. Revision zero obtains the current identity through the existing local baseline-status port even if `available=false`, without saving/incrementing the policy. At the hub, validate copied identity **and both revisions** against `^[a-f0-9]{64}$`, including local and remote results; length alone is insufficient. Remote decode validates the success/data shape and required fields before copying. Transport/malformed responses become declared `update.check-unavailable`; preserve existing typed authorization/target failures. An offline revision-zero UI read shows a translated neutral unavailable state with retry and no fabricated identity/edit controls. Saved policies retain their binding/stale/offline semantics; save revalidates live identity/revision, and an existing policy can still be disabled offline.
